# ADR-022 — فراخوانی ابزارها توسط مدل و چرخه ابزارهای بوم

## Context

تا پیش از این، اجرای نودها یک سناریوی ثابت و گام‌به‌گام را بدون دخالت تصمیم‌گیری مدل طی می‌کرد. برای تبدیل بوم به یک محیط عامل‌محور واقعی، مدل زبانی باید بتواند مستقیماً با فراخوانی ابزارها (Function Calling)، گراف و فایل‌ها را ویرایش کند و اطلاعات را بخواند.

## Decision

۱. چرخه ابزار در `askModel`: ابزارهای بوم در قالب JSON Schema به مدل تحویل داده شده و تا رسیدن به سقف `max_steps` در حلقه اجرا و پاسخ به مدل بازگردانده می‌شوند.
۲. ده ابزار استاندارد بوم پیاده‌سازی شدند:
   - `create_node`، `update_node`، `delete_node`
   - `create_edge`، `update_edge`، `delete_edge`
   - `get_canvas_overview`، `read_memory`، `write_memory`، `write_output`
۳. انطباق امنیتی کامل: هر فراخوانی با `hasTool` و مسیرهای مجاز خواندن/نوشتن (`allowed_read_paths` و `allowed_write_paths`) سنجیده شده و در صورت تخلف، وضعیت `denied` به مدل و دفتر وقایع (Run Ledger) ارسال می‌شود.
۴. امنیت کلید: کلید API فعلاً مستقیم در کلاینت برای استفاده شخصی است؛ برای محیط استقرار واقعی پروکسی سروری ضروری است.

## Consequences

- مدل به جای تولید متن منفعل، می‌تواند عامل تغییر فعال در گراف و حافظه باشد.
- هیچ ابزاری بدون مجوز صریح قرارداد نقش اجرا نمی‌شود.
- تمامی کنش‌های مدل با جزییات کامل در Run Ledger ثبت می‌شوند.
