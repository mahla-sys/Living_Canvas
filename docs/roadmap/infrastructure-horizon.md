# افق بلندمدت و الزامات زیرساختی

این سند قابلیت‌های احتمالی آینده را با تأثیرشان بر زیرساخت فعلی ثبت می‌کند. هدف این است که دیگر مجبور
نباشیم برای یک قابلیت ساده (مثل پالت رنگ) زیرساخت را بازسازی کنیم.

## اصول تغییرناپذیر

- پنج قانون اصلی معماری (`docs/ARCHITECTURE.md`) بدون تغییر باقی می‌مانند.
- هیچ قابلیتی که قانون ۱ (فایل‌ها بستر هستند) یا قانون ۲ (escape قبل از render) را بشکند پذیرفته نیست.
- هر قابلیت جدید **قبل از پیاده‌سازی** در این سند ثبت می‌شود و تأثیرش مشخص می‌شود.
- قابلیتی که اینجا ثبت نشود، نمی‌تواند وارد فاز بعدی شود.

## سه سؤال تصمیم‌گیری سریع

برای هر قابلیت جدید، اول این سه سؤال:

1. آیا `StorageAdapter` عوض می‌شود؟ → آری = ADR الزامی.
2. آیا schema نود یا یال عوض می‌شود؟ → آری = روی فایل‌ها اثر دارد و باید در `canvas.yaml` یا فایل نود بنشیند.
3. آیا `Executor` عوض می‌شود؟ → آری = روی موتور اجرا اثر دارد و باید در `ARCHITECTURE.md` ثبت شود.

## جدول قابلیت‌ها

| قابلیت | فاز | وضعیت | تأثیر بر زیرساخت | نیاز به ADR |
|---|---|---|---|---|
| **تم‌های بیشتر** | ۲ | **زیرساخت آماده** | دو توکن نقش + یک بلوک CSS؛ `check-palette.mjs` کنتراست **و تفکیک هیو** را می‌سنجد | ندارد — `adr-010` و `adr-011` کافی‌اند |
| تست تعاملی (jsdom) | ۱ | **انجام شد** | `@vitest-environment jsdom` per-file؛ ۱۹۳ تست داده‌ای روی node ماندند | ندارد |
| Run Scope (اجرای بخشی از خط لوله) | ۲ | ثبت‌شده، شروع نشده | `computeOrder` باید زیرمجموعه بگیرد و وابستگی را فقط در همان زیرمجموعه ببیند | **دارد** |
| کنترل‌های اجرا (Pause / Step / Stop) | ۲ | ثبت‌شده، شروع نشده | `execution.status` امروز `paused` دارد ولی موتوری که از آن برگردد ندارد؛ state machine لازم است | **دارد** |
| تب‌های Inspector (Status / Diary / Logs) | ۲ | ثبت‌شده، شروع نشده | `logs/<node>/` هست؛ «مصرف CPU/حافظه» منبع داده ندارد و باید تصمیم گرفته شود واقعی باشد یا شبیه‌سازی | **دارد** |
| جست‌وجو و آیکون وضعیت در پنل چپ | ۲ | ثبت‌شده، شروع نشده | فقط UI؛ تورفتگی ۱۶px و نگاشتِ وضعیت از `agent.status` | ندارد |
| نوار وضعیت پایین (بازچینی) | ۲ | ثبت‌شده، شروع نشده | فقط UI؛ `STATUS_BAR_HEIGHT` و `docs/patterns/layout-system.md` | ندارد |
| پنل‌های قابل جابه‌جایی (docking) | ۳ | باز | بازنویسی Layout System؛ `canvas.yaml` | **دارد** |
| چند بوم در یک پوشه (vault) | ۴ | باز | `StorageAdapter` + مسیردهی؛ `adr-005` امروز `proposed` است | **دارد** |
| حافظهٔ سه‌لایه (diary/history/core) | ۳ | باز | ساختار فایل‌های ایجنت، پوشهٔ `agent-<id>/` | **دارد** |
| Function Calling | ۲ | تصمیم گرفته شده | `TOOL_NAMES` + حلقهٔ `tool_calls` | **دارد** |
| نیازهای ایجنت (The Sims) | ۳ | باز | `AgentConfig` + فایل‌های جدید | **دارد** |
| رندر Canvas/WebGL | ۳–۴ | باز | جایگزینی لایهٔ رندر React Flow | **دارد** |
| i18n / چندزبانه | ۴ | باز | لایهٔ ترجمه + RTL؛ `check-english.mjs` امروز فارسی را فقط زیر `docs/` می‌پذیرد | **دارد** |
| همکاری بلادرنگ (CRDT) | ۴ | باز | `StorageAdapter` + تغییرات عمیق در store | **دارد** |
| ذخیره‌سازی ابری | ۴ | باز | `HttpStorageAdapter` امروز هست؛ Auth نیست | **دارد** |
| مدل‌های AI (GLM، Ollama) | ۲–۳ | نیمه‌باز | مسیریابی provider؛ `adr-008` موجود و `ollama:` کار می‌کند | دارد |
| شکل‌های سفارشی (SVG) | ۳ | باز | renderer جدید برای `nodeType` | **دارد** |

## قواعد افزودن قابلیت

1. در جدول بالا ثبت کن. ۲. سه سؤال را پاسخ بده. ۳. اگر ADR لازم دارد، **قبل از کد** بنویس.
۴. بعد از پیاده‌سازی وضعیت را `done` کن و فاز را مشخص کن.
۵. قابلیتی که بدون ثبت پیاده شود، نقضِ فرایند گزارش می‌شود.

## جمع‌بندی

این سند نقشهٔ راهِ زیرساختی است، نه فهرست آرزوها. هر ردیف باید تأثیرِ مشخص داشته باشد؛ اگر مبهم است،
نوشته نمی‌شود تا زمانش برسد.
