# سند مشخصات رابط کاربری و تجربه‌ی کاربری (UI/UX Spec) — Living Canvas

> **نسخه:** 1.0  
> **تاریخ:** 2026-09-01  
> **وضعیت:** پیش‌نویس برای بررسی و تأیید  
> **هدف:** تعریف دقیق ظاهر، رفتار و قابلیت‌های بصری Living Canvas که با هسته‌ی فایل‌محور هماهنگ باشد.

---

## ۱. اهداف

- ایجاد یک زبان بصری منعطف و قابل شخصی‌سازی که کاربر (و AI) بتوانند به‌راحتی ظاهر بوم، نودها و پنل‌ها را تغییر دهند.
- اطمینان از این‌که تمام تنظیمات ظاهری در همان ساختار فایل‌محور ذخیره می‌شوند و با Context Contract سازگارند.
- آماده‌سازی برای افزودن قابلیت‌های آینده بدون شکستن معماری فعلی.
- فراهم‌کردن تجربه‌ای که شبیه «نقاشی‌کردن» و «بازی‌های شهرسازی» باشد، نه یک فرم خشک.

---

## ۲. پس‌زمینه‌ی بوم (Background)

### ۲.۱ نیازها

- انتخاب رنگ ثابت یا گرادیان.
- نمایش نقطه‌چین با رنگ و فاصله‌ی قابل تنظیم.
- شاید در آینده بافت یا تصویر.

### ۲.۲ محل ذخیره‌سازی

در `canvas.yaml` بخش جدید `background`:

```yaml
background:
  type: "solid"               # solid | gradient | image (آینده)
  color: "#0b0d12"
  gradient:
    from: "#0b0d12"
    to: "#1a1c23"
    angle: 135
  dots: true
  dots_color: "rgba(255,255,255,0.04)"
  dots_gap: 16
```

### ۲.۳ رفتار

- کاربر از یک پنل تنظیمات (مثلاً در نوار بالا) بتواند این مقادیر را تغییر دهد.
- تغییرات بلافاصله اعمال و در `canvas.yaml` ذخیره شود.
- AI بتواند از طریق ابزار `update_canvas_config` این تنظیمات را تغییر دهد.

---

## ۳. ظاهر نودها (Node Appearance)

### ۳.۱ نیازها

- انتخاب شکل از میان شکل‌های آماده + امکان شکل سفارشی در آینده.
- کنترل کامل بر رنگ، ضخامت خط، شفافیت، شعاع گوشه‌ها، سایه، هاله‌ی نور (glow).
- قابلیت ذخیره‌ی استایل‌های دلخواه در کتابخانه و اعمال مجدد.

### ۳.۲ محل ذخیره‌سازی

در Frontmatter نود (بخش `style`) گسترش می‌یابد:

```yaml
style:
  fill: "rgba(20,22,28,0.6)"     # رنگ پس‌زمینه
  stroke: "#ffffff1a"            # رنگ خط دور
  strokeWidth: 1
  borderRadius: 12
  opacity: 100
  shadow: "soft"                 # none | soft | medium | strong
  glow:
    color: "#8b5cf6"
    intensity: 0.5               # 0 تا 1
    type: "outer"                # outer | inner | none
  customShape: null              # مسیر به فایل SVG در assets/shapes/
```

### ۳.۳ اشکال پیش‌فرض

- `rectangle` (مستطیل با گوشه‌های گرد قابل تنظیم)
- `circle`
- `diamond`
- `hexagon`
- `card` (کارت با هدر و بدنه)
- `empty` (بدون شکل، فقط محتوا)

### ۳.۴ کتابخانه‌ی استایل‌ها

- پوشه‌ی جدید `library/visual-styles/`
- هر استایل یک فایل JSON:

```json
{
  "id": "neon-agent",
  "name": "ایجنت نئونی",
  "nodeStyle": {
    "fill": "rgba(10,10,20,0.8)",
    "stroke": "#22d3ee",
    "glow": { "color": "#22d3ee", "intensity": 0.8 }
  },
  "animation": "pulse"
}
```

### ۳.۵ ابزارهای AI

- `save_visual_style` → ذخیره‌ی استایل فعلی در کتابخانه
- `apply_visual_style` → اعمال استایل روی نود
- `update_node` → تغییر مستقیم فیلدهای `style`

---

## ۴. حالت‌های نمایش نود (View Mode)

### ۴.۱ حالت‌های فعلی

- `dot`: فقط یک نقطه‌ی کوچک با رنگ نود. با هاور یا کلیک بزرگ‌تر می‌شود.
- `name`: فقط عنوان نود.
- `card`: کارت با عنوان و خلاصه‌ی کوتاه (از `description` یا `summary`).
- `markdown`: نمایش محتوای Markdown داخل نود.

### ۴.۲ نیازهای آینده

- حالت `list` (نمایش فشرده مثل آیتم‌های لیست)
- حالت `timeline` (نمایش وقایع به صورت خط زمانی)
- حالت `gallery` (نمایش تصاویر)
- حالت `kanban` (برای تسک‌ها)

### ۴.۳ محل ذخیره‌سازی

`viewMode` در Frontmatter نود.

### ۴.۴ رفتار

- کاربر از Inspector Panel یا با راست‌کلیک روی نود بتواند حالت را عوض کند.
- تغییرات در فایل نود ذخیره شوند.
- AI از طریق `update_node` بتواند `viewMode` را تغییر دهد.

---

## ۵. پنل‌های کناری (Side Panels)

### ۵.۱ ساختار فعلی

- **Inspector (چپ):** نمایش و ویرایش مشخصات نود/یال.
- **Library (راست):** المان‌های قابل درگ‌انددراپ (نود، شکل، نقش، قالب) + بخش قالب‌ها.
- **File Browser (راست):** درخت فایل‌های پروژه و نمایش محتوا.

### ۵.۲ نیازهای آینده

- امکان جابه‌جایی پنل‌ها (چپ/راست/پایین/شناور) توسط کاربر.
- امکان مخفی‌کردن/نمایش هر پنل.
- امکان افزودن پنل‌های جدید (مثلاً تایم‌لاین رویدادها، چت، خروجی‌ها) به‌صورت پلاگین.
- تعیین پیش‌فرض چیدمان در `ui.yaml`.

### ۵.۳ محل ذخیره‌سازی

یک فایل `ui.yaml` در ریشه‌ی پروژه:

```yaml
panels:
  inspector:
    visible: true
    default_position: "left"
    width: 320
  library:
    visible: true
    default_position: "right"
    width: 260
  files:
    visible: true
    default_position: "right"
    width: 280
  events:
    visible: false
    default_position: "bottom"
    height: 200
```

### ۵.۴ Inspector Panel — بخش‌های آینده

Inspector باید به‌تدریج شامل این بخش‌ها شود (هر کدام قابل جمع‌شدن):

- **عمومی:** عنوان، نوع نود، حالت نمایش، شکل، رنگ.
- **نقش و پرامپت:** `agent.system_prompt`, `agent.model`, `agent.role`.
- **ابزارها:** لیست چک‌باکس از `agent.tools`.
- **دسترسی‌ها:** نمایش درختی `context_contract` (خواندن/نوشتن).
- **جریان داده:** نمایش ورودی/خروجی‌های متصل به نود.
- **دفترچه خاطرات:** محتوای `memory/agents/<node-id>.md`.
- **لاگ‌ها و خروجی‌ها:** نمایش `logs/` و `outputs/`.

### ۵.۵ رفتار

- هر بخش به‌صورت آکاردئونی (collapsible) نمایش داده شود.
- ترتیب بخش‌ها قابل تنظیم در آینده باشد.

---

## ۶. دسترسی به‌صورت درختی

### ۶.۱ نیاز

نمایش `context_contract` به شکل یک درخت تعاملی که کاربر بتواند مسیرهای مجاز را ببیند و ویرایش کند.

### ۶.۲ طراحی

- دو ستون: «خواندنی‌ها» و «نوشتنی‌ها».
- هر کدام یک درخت از ساختار پوشه‌ها را نشان می‌دهند.
- کاربر با تیک‌زدن یا کلیک روی پوشه‌ها، مسیرها را اضافه/کم می‌کند.
- مسیرهای غیرمجاز قرمز یا غیرفعال نمایش داده شوند.

### ۶.۳ محل ذخیره‌سازی

در Frontmatter نود:

```yaml
context_contract:
  allowed_read_paths: [...]
  allowed_write_paths: [...]
```

---

## ۷. دفترچه خاطرات ایجنت (AI Diary)

### ۷.۱ نیاز

نمایش و ویرایش `memory/agents/<node-id>.md` در Inspector.

### ۷.۲ طراحی

- یک بخش در Inspector با آیکون کتاب/دفترچه.
- نمایش Markdown با قابلیت ویرایش.
- ذخیره‌ی خودکار یا دکمه‌ی ذخیره.

### ۷.۳ رفتار

- کاربر می‌تواند دستی یادداشت اضافه کند.
- ایجنت بعد از هر اجرا، به‌روزرسانی‌اش می‌کند (طبق MemoryManager).

---

## ۸. جریان داده و مراحل فکری (آینده)

### ۸.۱ نیاز

نمایش تایم‌لاین اجرا، رویدادها و خروجی‌های هر مرحله.

### ۸.۲ طراحی

- پنل پایین یا بخشی در Inspector به نام «جریان» یا «Trace».
- نمایش لیست زمانی از رویدادهای `Event Bus`.
- با کلیک روی هر رویداد، جزئیات (ورودی/خروجی/خطا) نمایش داده شود.

### ۸.۳ محل ذخیره‌سازی

در حال حاضر رویدادها در لحظه هستند.  
برای تاریخچه، از `history/` و `logs/` استفاده می‌شود.

---

## ۹. ابزارهای هوش مصنوعی مرتبط با UI

| ابزار | توضیح |
|-------|-------|
| `update_node` | تغییر فیلدهای ظاهری (style, viewMode, color و...) |
| `save_visual_style` | ذخیره‌ی استایل فعلی در `library/visual-styles/` |
| `apply_visual_style` | اعمال استایل از کتابخانه روی نود |
| `update_canvas_config` | تغییر پس‌زمینه و تنظیمات بوم |
| `get_ui_config` | خواندن چیدمان پنل‌ها (ui.yaml) |
| `update_ui_config` | تغییر چیدمان پنل‌ها |
| `convert_drawing_to_shape` | تبدیل نقاشی آزاد به شکل سفارشی (آینده) |

## ۱۰. اولویت‌بندی پیاده‌سازی

### فاز A (هسته‌ی بصری اولیه)

- گسترش `style` در Frontmatter نود با فیلدهای جدید (glow, shadow, borderRadius)
- افزودن `background` به `canvas.yaml`
- بهبود Inspector برای انتخاب رنگ، شکل، حالت نمایش
- افزودن `library/visual-styles/` و ابزارهای مربوطه

### فاز B (پنل‌های انعطاف‌پذیر)

- پیاده‌سازی `ui.yaml` و قابلیت جابه‌جایی پنل‌ها
- نمایش دسترسی‌ها به صورت درختی
- افزودن بخش دفترچه خاطرات در Inspector

### فاز C (ویژگی‌های پیشرفته)

- حالت‌های نمایش جدید
- تبدیل نقاشی به شکل سفارشی
- پنل جریان داده و تایم‌لاین
- تنظیم پذیری کامل ترتیب بخش‌های Inspector

- هوش مصنوعی می‌تواند بخواند و بنویسد.
